# Правила работы

- Новые возможности выполнять в ветках `feature/<название>`.
- Исправления выполнять в ветках `fix/<название>`.
- Ветки создавать от актуальной `main`.
- Изменения отправлять через pull request в `main`.
- PR проверяет и сливает пользователь.
- Не отправлять коммиты напрямую в `main`.
- Использовать ESLint и Prettier проекта.
- Перед сдачей запускать проверки и исправлять найденные проблемы.
- Исключение: в задаче первоначальной настройки линтера исходники не форматировать и автоисправления не запускать. Пользователь запускает их самостоятельно.
- Сообщения коммитов, заголовки и описания PR писать по-русски. Сообщение коммита описывает выполненное изменение, а не поручение агенту: например, «Настройка ESLint и Prettier» или «Настроен линтер», а не «Настроить линтер».
- Уточнение или исправление от пользователя считать продолжением текущей задачи. Применять его к подготовленным изменениям; спрашивать повторно только при необходимости нового разрешения или при реальной неоднозначности.

## Порядок получения разрешения

- Перед любым запросом разрешения сначала использовать вопрос со встроенным полем «Или напишите свой ответ», чтобы пользователь мог дополнить контекст или предложить правки. Не добавлять отдельный вариант «Дополнить контекст / внести правки»: для этого служит поле свободного ответа.
- Подготовленные изменения файлов показывать в отдельном файле предпросмотра или панели diff справа. Не вставлять большой diff в текст вопроса. До согласования не изменять исходный файл.
- Для коммита показывать точное сообщение и список файлов; для PR — заголовок и описание.
- После вопроса остановиться и ждать ответа пользователя. Не запускать зависимые действия и не открывать системное окно разрешения до согласования. Молчание не считать согласием.
- При получении правок обновить предпросмотр и показать его на подтверждение с возможностью свободного ответа.
- Если согласованная операция требует системного разрешения, открыть системное окно только после предварительного согласования. Агент не может добавить поле контекста в системное окно; оно не заменяет предварительный вопрос.
- При отклонении любого запроса разрешения сразу остановиться и ждать сообщения пользователя. Не выполнять следующие команды, не повторять запрос и не искать обходной способ. Причину отказа не угадывать.
- После отказа продолжать только в рамках дальнейших указаний пользователя.
- Эти правила применять во всех чатах, работающих с проектом.
