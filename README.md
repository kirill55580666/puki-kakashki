# Пуки & Какашки 💩🎀

Личный дневник на Vue 3, TypeScript и Supabase. Календарь, история, редактирование, статистика 7/30 дней, достижения, импорт/экспорт JSON. Без роутера и отдельного сервера.

Репозиторий: https://github.com/kirill55580666/puki-kakashki
Адрес GitHub Pages после успешного workflow: https://kirill55580666.github.io/puki-kakashki/

## Локальный запуск

Node.js 24, npm:

```sh
npm ci
npm run dev
```

Без переменных Supabase включается явно обозначенный локальный режим. Данные остаются в localStorage этого браузера. Облако и локальные записи не смешиваются; перенос — через экспорт/импорт.

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

## Проверка кода

После получения ветки установить зависимости командой `npm ci`.

```sh
npm run lint          # Проверка JS, TS и Vue, включая форматирование
npm run lint:fix      # Исправление доступных ESLint ошибок и форматирование JS/TS/Vue
npm run format       # Форматирование всех поддерживаемых файлов
npm run format:check # Проверка форматирования без изменения файлов
npm run typecheck    # Проверка типов через vue-tsc
```

Prettier задаёт отступ в два пробела, ширину строки 100 символов и отдельные строки для атрибутов Vue. ESLint проверяет JavaScript, TypeScript и основные правила Vue. Интеграция `prettier/prettier` позволяет исправлять форматирование JS/TS/Vue через `lint:fix`. Для CSS, JSON и Markdown используется `format`. SQL, зависимости, сборка и локальные файлы настроек исключены из форматирования.

Для Vue-файлов включено `semi: true`: разделители между командами inline-обработчиков сохраняются после форматирования. Можно писать несколько действий через `;` прямо в `@click`, без отдельной или стрелочной функции. Для остальных файлов остаётся `semi: false`.

`typecheck` запускает стандартную проверку типов `vue-tsc --noEmit`. Эта проверка также входит в `build`.

Изменения выполняются в ветках `feature/*` или `fix/*` и принимаются пользователем через pull request в `main`. После слияния существующий GitHub Actions workflow публикует сайт. Проверки стиля пока запускаются вручную. Правила работы агента сохранены в `AGENTS.md`.

## Подключение Supabase

1. Создать аккаунт и бесплатный проект на https://supabase.com/dashboard.
2. В SQL Editor выполнить `supabase/migrations/001_events.sql`, затем последующие SQL-файлы из `supabase/migrations` по порядку. Первая миграция создаёт таблицу, индекс и RLS, последующие добавляют необязательные тип стула и отметки самочувствия. Каждую применять один раз.
3. В настройках API проекта скопировать Project URL и публичный anon или publishable key. **Не использовать service_role или secret key.**
4. Скопировать `.env.example` в `.env`, заполнить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Перезапустить Vite.
5. В Authentication → URL Configuration указать Site URL — окончательный адрес GitHub Pages с завершающим `/`. В Redirect URLs добавить `http://localhost:5173/`, `http://127.0.0.1:5173/` и точный production URL, например `https://USERNAME.github.io/REPOSITORY/`. Для preview при необходимости добавить адрес порта 4173.
6. Включить Email provider, настроить подтверждение email. После регистрации приложение предлагает проверить письмо; ссылка возвращает в дневник. Восстановление пароля работает через письмо и отдельную форму нового пароля.
7. Для production настроить почтовую отправку в Supabase (Custom SMTP). Встроенная отправка ограничена и не предназначена для массовой production-авторизации. Бесплатность и лимиты выбранного почтового провайдера нужно проверить отдельно.

## GitHub Pages

1. Создать репозиторий и отправить файлы в ветку `main` (для бесплатного Pages использовать публичный репозиторий). `.env` и `node_modules` в Git не добавлять.
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions → Variables: задать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Это публичная клиентская конфигурация; защита данных обеспечивается RLS.
4. Запустить workflow `Deploy diary to GitHub Pages` или отправить коммит в `main`. Он выполнит тесты, TypeScript-проверку, сборку и публикацию. Без Supabase workflow намеренно останавливается, чтобы не опубликовать демо вместо полноценного приложения.
5. `base` вычисляется из конфигурации Pages автоматически, включая подпапку репозитория. Для ручной сборки можно задать `VITE_BASE_PATH=/REPOSITORY/`.

Деплой и настройку можно поручить агенту: потребуются вход в GitHub и Supabase и выбор проекта. Секретные ключи для frontend не нужны.

## Данные и ограничения

- В «Моём ритме» доступны режимы по дням (7/30 дней) и по часам выбранной даты. Нажатие на день открывает его 24-часовой график. Счётчики, распределение по частям суток и текстовые наблюдения используют именно выбранный день или период. Доли какашек и пуков рассчитываются отдельно; все Бристольские типы входят в какашки. Границы: ночь 00–06, утро 06–12, день 12–18, вечер 18–24; начало включено, конец не включён. Время — местное время события.
- Необязательное поле `symptoms` хранит боль 0–3, вздутие, а для дефекации — натуживание, неполное опорожнение, кровь и приём слабительного. `null` и отсутствующее значение означают «не указано»; явные `false` и `0` сохраняются как отрицательные ответы. Экспорт версии 3 включает самочувствие; импорт версий 1/2 без этих полей продолжает работать. JSON проверяется при импорте и ограничением базы.
- На странице «Мой ритм» вместо блока автоматических медицинских подсказок расположен отдельный опросник Wexner: восемь подтверждённых или ручных ответов, семь по 0–4 балла и помощь при опорожнении по 0–2. Результат 0–30 считается только при полных ответах. Сохраняются ответы, дата и версия `wexner-1996-ru-v1`; история сравнивает только полные оценки одинаковой версии. Изменение балла не интерпретируется как клиническое улучшение или ухудшение. Это перевод для дневника, не валидированная русская адаптация и не диагноз. Источники: [Agachan et al., 1996](https://pubmed.ncbi.nlm.nih.gov/8646957/) и [форма NHS](https://www.royalberkshire.nhs.uk/media/inmfdaiu/wexner-constipation-questionnaire_apr26.pdf).
- Записи за семь завершённых дней используются для справки и предложений при заполнении: дефекации, безуспешные попытки и наличие времени. В данном дневнике «пук» означает безуспешную попытку дефекации. Успешная дефекация не обнуляет попытки. Недельная сумма, среднее или максимум не преобразуются в ответ о попытках за 24 часа; диапазоны опубликованной шкалы местами пересекаются, категорию выбирает пользователь. Текстовую историю оценок можно скачать отдельно для врача. Оценки сохраняются в отдельной таблице Supabase, в демо — отдельным ключом localStorage; экспорт/импорт JSON событий и удаление событий их не затрагивают.
- Форма предлагает ответы из дневника с пометкой «Из дневника — проверь». Предложения видны в полях, но входят в результат только после явного подтверждения; любой ответ можно выбрать вручную. У каждого вопроса показаны исходные факты и ограничения. Для частоты дефекаций и безуспешных попыток есть отдельные подтверждения полноты записей. Для длительности нужен один однозначный диапазон во всех записанных попытках; среднее и максимум не подставляются. Пропуски остаются неизвестными, пересекающиеся границы не разрешаются автоматически. Это помощь в заполнении, а не валидированное вычисление Wexner из недельного дневника. Изменение событий или даты сбрасывает подтверждение полноты и принятые предложения; ручные ответы сохраняются. Смена аккаунта очищает всю форму.
- Необязательное поле `attempt_duration_minutes` хранит целое число минут от 1 до 1440 для успешной и безуспешной попытки. По умолчанию время неизвестно (`null`). Ползунок работает от 1 до 60 минут; точный ввод допускает более длительную попытку. Коричневое плавающее свечение плавно усиливается по шкале, отключается при `prefers-reduced-motion` и не обозначает медицинскую степень тяжести. Время видно в календаре и истории; экспорт JSON версии 4 и импорт сохраняют его. Старые файлы продолжают импортироваться.
- Перед публикацией этой версии один раз выполнить `supabase/wexner-schema.sql`: он добавляет необязательную длительность без изменения старых событий и создаёт таблицу оценок с RLS. Доступны только чтение и добавление собственных оценок для `authenticated`; анонимный доступ запрещён. Оценки неизменяемые: повторное заполнение создаёт новую запись. SQL оформлен отдельным скриптом для SQL Editor, поскольку Supabase CLI в окружении недоступен.
- `tests/wexner.test.ts` проверяет неполные ответы, 0/30 и 30/30, ограничения помощи, сравнения, сохранение и ошибки записи, импорт и редактирование длительности. `tests/wexner.sql` проверяет ограничения базы и изоляцию пользователей в транзакции с откатом.

- Для записей дефекации доступна Бристольская шкала: семь типов с собственными SVG-иллюстрациями и вариант «Тип не указан». Тип можно изменить при редактировании. Описания основаны на [шкале NHS](https://www.england.nhs.uk/wp-content/uploads/2023/07/Bristol-stool-chart-for-people-with-a-learning-disability-print-version.pdf), иллюстрации созданы для приложения.
- Календарь остаётся компактным: один общий значок 💩 и счётчик за день, отдельно 💨. Типы видны в списке выбранного дня и истории.
- Карточка «какашек в этом месяце» раскрывает семь типов и строку без типа с количеством и процентами. Итог включает все записи дефекации, в том числе старые. Период карточки — текущий календарный месяц по местному времени, независимо от переключателя 7/30 дней у графика активности. Проценты округляются.
- Поле `bristol_type` содержит число 1–7 или `null`; у пуков оно всегда `null`. Старые записи без поля считаются неуказанными. Экспорт сохраняет тип, импорт принимает старые файлы и проверяет новые значения.
- `tests/bristol.sql` проверяет ограничения типов, изменение типа и изоляцию пользователей в Supabase с откатом тестовых данных. `tests/rls.sql` проверяет базовые политики доступа.

- Все даты календаря вычисляются в локальном часовом поясе устройства. Сервер хранит timestamptz; смена часового пояса может переместить запись на другой календарный день.
- Статистика «дни без записи о дефекации» означает дни без соответствующей записи за выбранные последние 7/30 дней, включая сегодня. Этот счётчик не используется для медицинских выводов без подтверждения полноты дневника.
- Импорт до 5000 записей / 2 МБ за раз, с подтверждением. Он добавляет записи, не удаляет существующие; повторный импорт создаёт дубликаты. Чужие `id` и `user_id` игнорируются.
- История загружается постранично из Supabase; на экране отображается порциями по 50. Изменения с другого устройства доступны после обновления данных в настройках или перезагрузки страницы. Офлайн-синхронизации и realtime нет.
- При отсутствии сети операции показывают ошибку. После неоднозначного сетевого сбоя проверьте историю перед повторной отправкой: сервер мог успеть сохранить запись.
- В настройках можно удалить все свои события. Удаление самого аккаунта не реализовано; администратор проекта может удалить его в Supabase Auth, записи удалятся каскадно.
- `tests/rls.sql` проверяет права чтения, добавления, изменения, смены владельца и удаления для двух тестовых пользователей внутри транзакции с откатом. Эта проверка не заменяет сквозную проверку отправки писем и входа через браузер.
- Шрифты загружаются с Google Fonts; при недоступности используются системные. Иллюстрация — собственный SVG, внешних изображений нет.

Код: `src/pages` — экраны, `src/components` — диалоги и иллюстрация, `src/lib/repository.ts` — заменяемый интерфейс хранилища, `src/state.ts` — состояние и асинхронные операции.
